# DS18B20 Endpoints

## GET /ds18b20/scan
**Path:** `/ds18b20/scan` · **Method:** GET

**Purpose:** Scan the DS18B20 1-Wire bus for sensors.

**Response** (`Ds18b20ScanResponse` — see [messages.md#ds18b20scanresponse](messages.md#ds18b20scanresponse))
- CoAP codes: `2.05 Content` on success; `5.03 Service Unavailable` if no DS18B20 bus is configured; `5.00` on scan failure.

**Example request/response** (live device, 2026-08-06 — bus configured but no sensors):
- Request: (empty)
- Response 2.05: `{devices:[], device_count:0}`
- When no bus is configured, the handler returns `5.03` (no body); that is a valid outcome, not an error.

**Notes:** A `5.03` is a valid outcome when no bus is configured; it is not an error.

## POST /ds18b20/config
**Path:** `/ds18b20/config` · **Method:** POST

**Purpose:** Configure (or reinitialize) the DS18B20 1-Wire bus on a GPIO.

**Request** (`Ds18b20ConfigRequest` — see [messages.md#ds18b20configrequest](messages.md#ds18b20configrequest))
- `gpio`: 0-48, must not be a reserved or already-claimed pin.

**Response** (`StatusResponse` — see [messages.md#statusresponse](messages.md#statusresponse))
- CoAP codes: `2.04 Changed` with `ok:true`; `4.00 Bad Request` on init/claim failure.

**Notes:** Persists the bus GPIO; a `ConfigFile` does not carry this field, so a config import does not clear it.
